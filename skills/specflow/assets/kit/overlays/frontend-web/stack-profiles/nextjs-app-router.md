# Stack profile nextjs-app-router

## 1. Scope

Web UI written in TypeScript on Next.js App Router and React, built with Tailwind CSS and shadcn/ui, server data through TanStack Query, forms with React Hook Form and Zod, display strings with next-intl, API types generated from OpenAPI. The profile matches a project generated by `create-next-app` 16.3.5 (App Router, `src/`, Tailwind, ESLint) plus `shadcn init` and the libraries in §2. The versions were fixed on 2026-09-22 and tested together on Node.js 24.21.0: type generation, typecheck, lint, unit tests, integration tests with a mock API, build, and e2e with an accessibility scan and visual regression all passed on a trial project; upgrade versions under the Dependency Policy in ARCHITECTURE §2.2.

Notes:

- The types generated in `src/lib/api/schema.d.ts` are not committed, so `{{CODEGEN_CMD}}` runs first on a new machine, in CI, in the image build step and after every update of `openapi/api.yaml`.
- `{{BUILD_CMD}}` needs `NEXT_PUBLIC_API_BASE_URL` because public variables are embedded at build time and `src/config/env.ts` reports an error when it is missing: on a developer machine set it in `.env.local`; CI and the image build step pass the value of the target environment.
- `{{E2E_TEST_CMD}}` builds and then runs the application on port 3100 (the `webServer` configuration in §4.1). The machine that runs the tests needs the Playwright browser: `npx playwright install --with-deps chromium`.
- Visual regression baseline images depend on fonts and the operating system: create and update the baselines (`npx playwright test --update-snapshots`) only on the same image as CI, then commit them.
- The profile's default coverage threshold is 80% for `src/features/**`; the SRS may set a different threshold in NFR-MAINT.

### 4.2. API types and client (for ARCHITECTURE §5)

<!-- PROFILE-CONTENT: arch.schema -->
### Stack API Types & Client

- `{{CODEGEN_CMD}}` generates `src/lib/api/schema.d.ts` from `openapi/api.yaml`; the source document needs an `info` block and a schema for every response that the UI reads.
- The shared client is created with `openapi-fetch` and takes `fetch` at call time, so the test mock API (MSW) and other `fetch` wrappers can intercept requests. The authentication header is attached by the `apiClient.use(...)` middleware following the session mechanism in ARCHITECTURE §6.1.
- A query cache key is an array of the module name, the resource name and the parameters, for example `["{{MODULE_SLUG}}", "list", { cursor }]`; write mutations turn off automatic retry.
- The form schema lives in `src/features/{{MODULE_SLUG}}/{{MODULE_SLUG}}.schema.ts` and is connected to the form with `zodResolver`.

```typescript
import createClient from "openapi-fetch";
import { env } from "@/config/env";
import type { paths } from "./schema";

export const apiClient = createClient<paths>({
  baseUrl: env.NEXT_PUBLIC_API_BASE_URL,
  fetch: (request) => globalThis.fetch(request),
});
```

### 4.3. Stack UI conventions (for ARCHITECTURE §7)

<!-- PROFILE-CONTENT: arch.conventions -->
### Stack Implementation Notes

- `page.tsx` is a server component; a component with a form, state or events goes in `src/features/` with `"use client"`.
- The `Loading` state of a route uses `loading.tsx`; the `Error` state of a route uses `error.tsx` (a client component that receives `error` and `retry`; from Next.js 16.3 `retry()` is the stable API to reload the segment). The state of each data region comes from `isPending`, `isError`, `isSuccess` of TanStack Query.
- Display strings: next-intl does not route by locale; one file per locale in `messages/` (for example `messages/vi.json`), `src/i18n/request.ts` uses `getRequestConfig`, `next.config.ts` is wrapped with `createNextIntlPlugin()`, and the root layout is wrapped with `NextIntlClientProvider`. A server component uses `getTranslations`, a client component uses `useTranslations`.
- `QueryClientProvider` lives in `src/lib/query-provider.tsx` (a client component) and wraps the content in the root layout.
- Form: `useForm` with `zodResolver`; an invalid field has `aria-invalid` and an `aria-describedby` that points to the error message.
- The `Idempotency-Key` is generated with `crypto.randomUUID()` when the user submits and kept in a `useRef` together with the submitted content; when the outcome is unknown, the form switches to read-only (`disabled` on the fields) and the resubmit button reuses that key and content pair, following the API call rule above. The submitting flag is also kept in a `useRef` and set synchronously before the API call.
- A server component or route handler that calls the API on behalf of the user reads `x-forwarded-for` with `headers()` from `next/headers`, takes the last element (the address that the web load balancer wrote) and sends an `X-Forwarded-For` that contains only that address. Next.js does not overwrite this header when the client has sent it, so do not forward the received value as is.
- Environment variables: only a variable with the `NEXT_PUBLIC_` prefix is embedded into code that runs in the browser, at build time, and only when the code reads it as a property such as `process.env.NEXT_PUBLIC_API_BASE_URL`, not by a string index. `src/config/env.ts` is the only place that reads variables and validates them with Zod:

  ```typescript
  import { z } from "zod";

  const EnvSchema = z.object({ NEXT_PUBLIC_API_BASE_URL: z.url() });

  export const env = EnvSchema.parse({ NEXT_PUBLIC_API_BASE_URL: process.env.NEXT_PUBLIC_API_BASE_URL });
  ```
- Tokens: the `semantic` tokens of `docs/design-system/tokens.json` become CSS variables in the `:root` of `src/app/globals.css` (another mode overrides them in the matching mode selector); the `@theme inline` block maps those variables to Tailwind utilities; the shadcn variables (`--background`, `--foreground`, `--primary` and the rest) point to the token variables and hold no value of their own. The `base-nova` style is only a component skeleton; its colors and spacing change through tokens. Style Dictionary is an option to generate files and is not installed by default; until it is used, write the CSS variables by hand following the variable names in CONVENTIONS §10.7 and keep them in sync with `tokens.json`. `globals.css` is the only place that holds raw color, spacing, radius and font-size values.
- Next.js inserts an element `#__next-route-announcer__` with `role="alert"`; a test that queries an error message filters by content, for example `getByRole("alert").filter({ hasText: ... })`.

## 5. Stack Conventions

- `tsconfig.json` follows the scaffold (`module: esnext`, `moduleResolution: bundler`, `strict`, alias `@/*` pointing to `src/*`), plus `noUncheckedIndexedAccess: true`.
- Add a UI component with `npx shadcn@4.21.0 add <name>`; the generated component lives in `src/components/ui/` and is edited like project code.
- `create-next-app` generates `AGENTS.md`, which holds the Next.js guidance block, and a one-line `CLAUDE.md` with `@AGENTS.md`. Keep `AGENTS.md` as is: while this file exists, `next dev` updates only the block in `AGENTS.md`; when the file is deleted, `next dev` writes the block into `CLAUDE.md`. If the web application is at the repo root: replace the scaffold's `CLAUDE.md` with the file generated from the Agent Context Template, then add the line `@AGENTS.md` at the end so that Claude Code loads the version-specific Next.js guidance. If the web application is in a subdirectory (a fullstack project): keep the scaffold's one-line `CLAUDE.md` in that directory as is; the project's Agent Context lives at the repo root.
- The form schema copies the limits from the API's SPEC and has boundary tests; sharing a schema package with the API needs an ADR.
