# Stack profile node-nestjs-prisma

## 1. Scope

Backend API written in TypeScript running on Node.js, with the NestJS framework as an ES module (ESM, the NestJS 12 default), the Prisma ORM and a PostgreSQL database. The profile matches a project generated by `nest new` of NestJS 12 (ESM, Vitest, oxlint), plus Prisma and the libraries in §2. The versions were fixed on 2026-09-22 and tested together: typecheck, type-aware lint, unit tests, e2e tests and build all passed on a trial project; upgrade versions under the Dependency Policy in ARCHITECTURE §2.2.

Notes:

- The Prisma Client is not committed and Prisma 7 does not generate the client when the package is installed, so `{{CODEGEN_CMD}}` runs first on a new machine, in CI, in the container image build step (before `{{BUILD_CMD}}`) and after every change to `prisma/schema.prisma`.
- `migrate diff --from-migrations` needs a shadow database (`SHADOW_DATABASE_URL`, only in dev and CI). `prisma.config.ts` reads environment variables with `process.env` so that `prisma generate` and `migrate deploy` run when an unrelated variable is absent.
- `npx prisma` uses the locally installed version; do not run `npx prisma` where the package is not installed, because npx would download the latest version from the registry.
- `prisma` 7.10.0 pins `deepmerge-ts` 7.1.5 and `mysql2` 3.15.3, two versions with high-severity vulnerabilities that make `{{AUDIT_CMD}}` fail. `package.json` records `"overrides": { "deepmerge-ts": "8.0.2", "mysql2": "3.24.4" }`; `prisma validate`, `generate`, `migrate dev`, `migrate deploy`, `migrate diff` were tested with the two overrides.
- `redocly.yaml` at the project root contains `extends: [recommended]` and `telemetry: off`, so the OpenAPI document lint command does not send usage data outside.
- The profile's default coverage threshold is 80% for `src/modules/**/*.service.ts`; the SRS may set a different threshold in NFR-MAINT.

### 4.2. Prisma schema (for ARCHITECTURE §5)

<!-- PROFILE-CONTENT: arch.schema -->
### Prisma Schema Conventions

The generator and datasource blocks follow Prisma 7; the connection URL lives in `prisma.config.ts`, not in the schema. `moduleFormat = "esm"` matches a NestJS 12 project as an ES module; the generated client imports with the `.js` extension, compatible with `module: nodenext`.

```prisma
generator client {
  provider     = "prisma-client"
  output       = "../src/generated/prisma"
  moduleFormat = "esm"
}

datasource db {
  provider = "postgresql"
}
```

```typescript
import { config } from "dotenv";
import { defineConfig } from "prisma/config";

config({ quiet: true });

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: { path: "prisma/migrations" },
  datasource: {
    url: process.env["DATABASE_URL"],
    shadowDatabaseUrl: process.env["SHADOW_DATABASE_URL"],
  },
});
```

| Concept | How to write it in Prisma |
| --- | --- |
| Model and table name | Singular `PascalCase` model, `@@map("snake_case_plural")` |
| Field and column name | `camelCase` field, `@map("snake_case")` |
| UUIDv7 primary key | `id String @id @default(uuid(7)) @db.Uuid`; UUIDv4 uses `@default(uuid())` |
| String | `String @db.VarChar(n)` with a maximum length that matches validation; `@db.Text` only when there is no business limit |
| Currency | `Decimal @db.Decimal(12, 2)` |
| Time | `DateTime @db.Timestamptz(3)`; `createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)`; `updatedAt DateTime @updatedAt @map("updated_at") @db.Timestamptz(3)` |
| Soft delete | `deletedAt DateTime? @map("deleted_at") @db.Timestamptz(3)` |
| Foreign key | `@relation(fields: [xId], references: [id], onDelete: Restrict)` with `@@index([xId])` |
| Composite unique | `@@unique([fieldA, fieldB])` |
| Enum | `enum` with `UPPER_SNAKE` values, matching SRS §4.2 |
| Check constraint | A Prisma schema cannot declare `CHECK`: create the migration with `prisma migrate dev --create-only`, add the SQL statement to the generated file, and only then apply it; record it in SPEC §4 |

Data access:

- `PrismaService` in `src/infrastructure/database/` extends `PrismaClient` with `adapter: new PrismaPg({ connectionString })` and is injected into repositories; a service does not call Prisma directly.
- Transaction: `prisma.$transaction(async (tx) => { ... }, { isolationLevel })`, opened in the service, with `tx` passed down to the repository.
- Conditional atomic update: `updateMany({ where: { id, field: { gte: amount } }, data: { field: { decrement: amount } } })`, check that `count` is 1; a `count` of 0 means the condition is not met.
- Lock by a business key inside a transaction (for example, to serialize requests with the same idempotency key): `` tx.$executeRaw`SELECT pg_advisory_xact_lock(hashtextextended(${key}, 0))` ``; the lock is released automatically when the transaction ends. The parameter is passed through a tagged template, so it is already parameterized.

### 4.3. Stack communication conventions (for ARCHITECTURE §7)

<!-- PROFILE-CONTENT: arch.conventions -->
### Stack Implementation Notes

- Relative imports in source code carry the `.js` extension (for example `./{{MODULE_SLUG}}.service.js`) because the project uses `module: nodenext`.
- Validate requests with the shared `ZodValidationPipe` in `src/shared/pipes/`; the controller attaches the pipe with the schema of each DTO: `@Body(new ZodValidationPipe(Schema)) body: Request`.
- The global exception filter in `src/shared/filters/` maps every error to the envelope in §6.2: a business error carries a code from §7.1; a validation error becomes `VALIDATION_ERROR` with `details`; a framework `HttpException` is mapped by HTTP status using the mapping table above (for example `ThrottlerException` becomes `429 RATE_LIMITED`, keeping the `Retry-After` header); an unexpected error becomes `INTERNAL_ERROR` and is logged in full.
- Rate limiting: use a guard that extends `ThrottlerGuard` in `src/shared/guards/`.
  - Headers: `@nestjs/throttler` writes `X-RateLimit-*` by default; the guard sets `protected headerPrefix = "RateLimit"` to emit `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`. Keep the throttler named `default`, because a throttler with another name adds that name as a suffix of the headers.
  - Counting key: the guard overrides `getTracker` and returns the `sub` of the access token on an authenticated route and the client IP on a public route (a route that needs another key, such as sign-in counting by IP and email, records it in the SPEC). By default the throttler counts by `req.ip`.
  - Client IP: `main.ts` calls `app.set("trust proxy", ...)` with the list of internal address ranges of every trusted proxy: the load balancer and the servers of another surface that call the API on behalf of the user (for example the web's server rendering, which forwards only one client address written by its own load balancer); Express skips the trusted addresses in `X-Forwarded-For` to obtain the real client IP. With only one load balancer in front, use `1`. Without this configuration, `req.ip` is the address of the nearest proxy and every client that passes through that proxy shares one counter.

```typescript
import { Injectable, type PipeTransform } from "@nestjs/common";
import type { ZodType } from "zod";
import { ValidationError } from "../errors/validation.error.js";

@Injectable()
export class ZodValidationPipe implements PipeTransform {
  constructor(private readonly schema: ZodType) {}

  transform(value: unknown): unknown {
    const result = this.schema.safeParse(value);
    if (!result.success) {
      throw new ValidationError(
        result.error.issues.map((issue) => ({ field: issue.path.join("."), issue: issue.message })),
      );
    }
    return result.data;
  }
}
```

## 5. Stack Conventions

- `tsconfig.json` follows the NestJS 12 scaffold (`module` and `moduleResolution` are `nodenext`, `experimentalDecorators`, `emitDecoratorMetadata`), plus `strict: true` and `noUncheckedIndexedAccess: true`.
- A feature module is registered in `src/app.module.ts`; another module uses only providers that are `exports`ed.
- `nestjs-pino` generates or receives a correlation ID from the `x-request-id` header and attaches it to every log record.
- `dotenv` 18 prints a message when it loads variables; call `config({ quiet: true })` as in `prisma.config.ts`.

## 6. Project Setup

1. `npx @nestjs/cli@12.0.3 new <name> --skip-git --package-manager npm --no-observe` (ESM, Vitest, oxlint are the defaults).
2. Install the libraries with the exact versions in §2, for example `npm install --save-exact prisma@7.10.0 @prisma/client@7.10.0 @prisma/adapter-pg@7.10.0 zod@4.6.5 dotenv@18.0.2 @nestjs/jwt@12.0.2 @nestjs/throttler@6.7.0 argon2@0.45.1 nestjs-pino@5.2.0 pino@10.3.1 pino-http@11.0.0` and `npm install --save-exact --save-dev @testcontainers/postgresql@12.1.0 @redocly/cli@2.54.0`; pin the devDependencies that the scaffold generates to the exact versions in §2.
3. Two fixes for the scaffold's sample files: the sample e2e test imports `supertest/types` without the extension, which is error TS2307 under `nodenext`, so change it to `supertest/types.js`; the sample spec uses the global `describe`, so it needs `globals: true` as in the configuration in §4.1.
4. Replace the scaffold's `vitest.config.ts`, `vitest.config.e2e.ts` and `.oxlintrc.json` with the configuration in §4.1, then change the `test:e2e` script in `package.json` to `vitest run --project e2e`; create `prisma/schema.prisma` and `prisma.config.ts` following §4.2; run `npx prisma generate`.
5. The scaffold adds the devDependency `@nestjs/mau` and a `deploy` script for the NestJS Mau platform; this package pulls in a dependency with a high-severity vulnerability. A project deployed with containers under ARCHITECTURE §8 removes both; a project that uses NestJS Mau records an ADR.
6. Add the `overrides` block and `redocly.yaml` following the notes in §3; run `npm install` and then `{{AUDIT_CMD}}`.
