# Mobile Golden Rules

<!-- fill: Copy to .claude/rules/mobile-golden-rules.md at Stage 2. paths lists the app's source folders per ARCHITECTURE §4, one glob per element. assembled_from records "overlays/mobile-app/agent-rules/mobile-golden-rules.md@<template_version>" and the stack profile used. -->

- Separate the layers: a screen only composes feature components; read data through the feature's hook from the local database; MUST NOT call the API or run SQL queries in a UI component.
- A write operation updates the local record and adds the change to the queue in the same transaction; MUST NOT call the API's write endpoint from a screen. Only the sync engine sends changes to the API.
- Each change has its own idempotency key stored with the change; read and mark the change as sent in the same transaction before sending the request; a resend uses exactly the old key and content. MUST NOT edit the content of a change that has been sent or is being sent; a new edit becomes a new change queued behind it.
- Changes of one record are sent in the exact order they were created; a change waiting for its retry time holds back the later changes of the same record, and does not hold back changes of other records.
- Arbitrate conflicts by the version issued by the API and the strategy in the ADR; MUST NOT use the device clock to decide which version wins.
- MUST NOT drop an unsynced change without the user knowing: sign-out, data deletion, a conflict and a rejection are all shown first.
- Every screen implements all five UI states; a record that can be edited offline shows its sync status per SPEC §3.
- Every display string is fetched through a locale string key; MUST NOT hard-code display text in a component.
- MUST NOT write raw color, spacing, radius or font size in UI code; only read the tokens of `docs/design-system/tokens.json` through the app's theme. That theme file (the theme object), written by hand or generated by a tool, is the only place allowed to hold raw values and MUST match `tokens.json`. The theme of the UI library changes only through tokens.
- Tokens and secrets are stored only in the OS keystore; MUST NOT write a token or personal data to logs, crash reports or unencrypted storage outside the declared local database.
- Ask for an OS permission right before using the feature that needs it, with an explanation; handle the denied case.
- Migrations of the local database are add-only; MUST NOT edit, merge or delete a released migration.
- Accessibility: every interactive element has a label and a role for screen readers, a touch target of at least 44 × 44 pt on iOS and 48 × 48 dp on Android, and text that scales with the system font size; the full criteria are in `specflow/CONVENTIONS.md` §10.2.
